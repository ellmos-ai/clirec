# Windows-E2E-Nachweis vom 2026-07-28

## Umfang

Dieser Lauf prüft zwei Abnahmepunkte: den realen `open-compute`-Replay (A) und
den deutschen Dead-Key-Capture (B). Er trennt nachgewiesene Laufzeitergebnisse
ausdrücklich von Gates, für die der aktuelle Host die benötigte Hardware oder
Eingabemethode nicht bereitstellt.

## Umgebung

- Windows 11, Build 26200, Python 3.12
- aktive Sitzung: RDP
- virtueller Desktop: `(0, 0)`, 1920×1080
- erkannte Monitore: 1
- effektive DPI: 96×96
- aktives und einzig installiertes Tastaturlayout: Deutsch (`0x04070407`)
- `open-compute`: Commit `cbd75ac`
- produktiver Executor: `open_compute.drivers.local.LocalExecutor`

Damit ist ein realer Windows-GUI-Lauf möglich. Ein IME-Capture und ein echter
Multi-Monitor-Mixed-DPI-Lauf sind in dieser Umgebung nicht möglich.

## Abnahmepunkt A: realer `open-compute`-Replay

Eine temporäre `.clirec`-Aufnahme wurde über den echten `oc rec`-Dispatcher mit
`--yes` gegen einen eindeutig identifizierten Notepad-Tab abgespielt. Vor dem
Senden wurde das Ziel-HWND als Vordergrundfenster geprüft. Die Aufnahme:

1. fokussierte die Editorfläche,
2. leerte einen möglichen Altzustand,
3. setzte `${message}` ein,
4. speicherte die Datei,
5. kopierte den Inhalt zur unabhängigen Rückleseprüfung.

Ergebnis:

```text
replay: total=7 ok=7 fallbacks=0 failures=0
EXPECTED=clirec-abnahme-a-Parameter-ÄÖÜ-é-漢字
CLIPBOARD_MATCH=True
SAVED_MATCH=True
```

Damit sind produktiver Executor, Parameterersetzung, Unicode-Übertragung,
Inter-Step-Timing und sichtbare Wirkung in einer realen Ziel-GUI nachgewiesen.
Zusätzlich bestanden alle 452 Tests des benachbarten `open-compute`-Checkouts
gegen diesen `clirec`-Stand.

## Abnahmepunkt B: deutscher Dead-Key

Der echte `WinApiCaptureBackend` zeichnete auf dem deutschen Layout die
Tastenfolge `^` und `e` auf. Vor der Korrektur entstand zusätzlich zum
zusammengesetzten Zeichen ein nicht portabler Replay-Schritt `key vk_220`.
Der Capture-Pfad unterscheidet den Dead-Key nun von gewöhnlichen
nicht-druckbaren Tasten.

Nach der Korrektur:

```text
RAW_EVENTS=dead_key(vk_220), key_up(vk_220), char(ê), key_up(e)
CAPTURED_STEPS=type("ê")
CAPTURED_TEXT=ê
REPLAY_REPORT=total:1,ok:1,fallbacks:0,failures:[]
REPLAY_MATCH=True
```

Die aus dem realen Hook erzeugte Aufnahme wurde nach dem Leeren des Editors über
den produktiven `open-compute`-Executor wieder abgespielt. Datei und
Zwischenablage enthielten anschließend jeweils exakt `ê`.

Die vollständige `clirec`-Suite bestand danach mit 89 Tests; Ruff-Lint,
Ruff-Formatprüfung und `compileall` waren ebenfalls sauber.

## Offene Abnahme-Gates

- **IME:** Auf dem Host ist kein IME installiert; verfügbar ist ausschließlich
  das deutsche Tastaturlayout. Ein echter IME-Commit kann daher nicht erfasst
  und reproduziert werden.
- **Multi-Monitor-Mixed-DPI:** Die RDP-Sitzung stellt genau einen Monitor mit
  1920×1080 bei 96 DPI bereit. Ein echter Lauf über zwei Monitore mit
  unterschiedlicher Skalierung kann daher nicht stattfinden.

Diese beiden Punkte dürfen nicht durch simulierte Geometrie- oder Unicode-Tests
als live abgenommen ausgegeben werden. Abnahmepunkt B bleibt bis zu einem Lauf auf
passender Hardware mit installiertem IME offen.
